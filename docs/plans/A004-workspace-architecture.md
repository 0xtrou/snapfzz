# Workspace Architecture

A Snapfzz project is a **folder on disk**. The folder contains the user's actual code plus a `.snapfzz/` directory with all launcher config, history, and state. Like `.vscode/`, `.cursor/`, `.git/`.

The user owns their files. The launcher orchestrates around them.

## Key Design Decisions

### 1. Project = Folder. Period.

A project IS its folder. No database entry required to "register" a project. Drop a folder with `.snapfzz/` anywhere and the launcher can open it. Move the folder, rename it — everything still works because paths inside `.snapfzz/` are relative.

```
# The launcher discovers projects by scanning for .snapfzz/ directories
# No central project database needed
```

### 2. `.snapfzz/` is Optional to Git

The user decides whether to commit `.snapfzz/` to their repo or gitignore it.

**Commit it (recommended for teams):**
- Requirements, ratings, quality reports are shared
- New team member opens project, sees full history
- Build decisions are documented

**Gitignore it (solo/private):**
- Keeps repo clean
- Agent sessions have API key references
- Snapshots are large binary files

Default `.gitignore` addition:
```gitignore
# Snapfzz Startup Launcher
.snapfzz/snapshots/
.snapfzz/session/
```

This gitignores binary/session state but keeps config, requirements, ratings, and quality reports versioned.

### 3. Global State Lives Outside Projects

User preferences, LLM keys, cross-project memory, cached images, and agent snapshots live in `~/.snapfzz/` (or platform-appropriate app data directory).

| Data | Location | Why |
|---|---|---|
| LLM API keys | `~/.snapfzz/config.json` | Never inside a project (security) |
| User preferences | `~/.snapfzz/config.json` | Shared across all projects |
| Cross-project memory | `~/.snapfzz/memory/` | The moat — accumulates forever |
| OCI image cache | `~/.snapfzz/images/` | Shared across projects (saves disk) |
| Agent snapshots | `~/.snapfzz/snapshots/` | Base snapshots (project-specific ones in `.snapfzz/`) |
| Eval datasets | `~/.snapfzz/eval/datasets/` | Benchmark inputs (versioned with app updates) |

Platform paths:
```
macOS:   ~/Library/Application Support/com.snapfzz.launcher/
Windows: %APPDATA%/snapfzz-launcher/
Linux:   ~/.local/share/snapfzz-launcher/
```

### 4. Everything is Human-Readable

No SQLite. No binary formats (except snapshots). Every config and state file is JSON or Markdown that the user can read, edit, and version control.

| File | Format | Editable by User? |
|---|---|---|
| `config.json` | JSON | ✓ Yes — change settings manually |
| `requirements.md` | Markdown | ✓ Yes — edit requirements before Discover |
| `discovery.json` | JSON | Read-only (agent output) |
| `rating.json` | JSON | Read-only (agent output) |
| `build-log.jsonl` | JSONL (append-only) | Read-only (audit trail) |
| `quality-report.json` | JSON | Read-only (agent output) |
| `ship-manifest.json` | JSON | ✓ Yes — update URLs, IDs manually |
| `decisions.jsonl` | JSONL (append-only) | Read-only (memory) |
| `*.snapshot` | Binary (BoxLite) | Not editable |

### 5. Append-Only Logs for History

Build log and decision log are JSONL (one JSON object per line, append-only). Never overwritten. Full audit trail.

```jsonl
{"ts":"2026-04-02T10:30:00Z","agent":"scaffold","action":"clone","repo":"startupsg/incorp","duration_ms":12000}
{"ts":"2026-04-02T10:30:12Z","agent":"customize","action":"rename","from":"incorp","to":"sea-atlas"}
{"ts":"2026-04-02T10:32:45Z","agent":"customize","action":"add_jurisdiction","country":"VN","files_added":2}
{"ts":"2026-04-02T10:35:10Z","agent":"harden","action":"add_error_boundary","component":"App","file":"app/layout.tsx"}
{"ts":"2026-04-02T10:36:02Z","agent":"test","action":"run_tests","passed":14,"failed":0,"duration_ms":45000}
```

## How The Launcher Interacts With the Workspace

### Opening a Project

```
1. User clicks "Open" on a project in workspace
2. Launcher reads <project>/.snapfzz/config.json
3. Loads stage, session state, history
4. Boots appropriate BoxLite VM (from project snapshot if exists, else global snapshot)
5. Mounts <project>/ as volume inside the VM
6. User's code is accessible to agents inside the VM
```

### Creating a New Project

```
1. User types idea and clicks "Start"
2. Launcher creates ~/snapfzz-projects/<project-name>/
3. Creates .snapfzz/ with config.json (stage: "clarify")
4. Boots ClarifyAgent VM
5. Agent conversation begins
```

### Agent Writing Code

```
1. BuildAgent inside BoxLite VM writes to /workspace/app/page.tsx
2. /workspace/ is mounted from ~/snapfzz-projects/sea-atlas/
3. File change appears on host filesystem
4. Vite dev server (in Preview Box) detects change via filesystem watcher
5. HMR fires → preview updates
```

### Closing and Resuming

```
1. User closes app
2. Launcher saves session state to .snapfzz/session/<agent>.json
3. BoxLite VMs save state (persistent by design)
4. App exits

5. User reopens app
6. Launcher scans workspace root for .snapfzz/ directories
7. Workspace shows all projects with their stages
8. User clicks "Resume" → VM restores from snapshot → exact state
```

```

  Default: ~/snapfzz-projects/
```

| — | — | `eval/` (benchmark history) |
| — | — | `memory/` (decision log) |

## Design Rules

1. **A project is a folder.** No database. No registration. Folder + `.snapfzz/` = project.
2. **`.snapfzz/` is the ONLY launcher artifact.** Everything else in the folder is the user's code.
3. **Human-readable by default.** JSON and Markdown. No proprietary formats.
4. **Append-only for history.** Build log and decisions never overwritten. Full audit trail.
5. **Global state is separate.** API keys, memory, images, base snapshots live in app data directory.
6. **Snapshots are binary but expendable.** Delete them = next boot is slower (cold start). Data is not lost.
7. **The user can `git init` their project.** `.snapfzz/` integrates naturally with git. Sensible gitignore defaults.
8. **Moving the folder moves the project.** No broken symlinks, no path registry. Everything is relative.
